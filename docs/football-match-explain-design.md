# 足球「AI 賽後解說」保留設計（未上線）

> 待網站穩定、成本可控時先按本文重開。**呢份文件只係設計紀錄，冇任何程式在行。**

## 一、功能目標

球迷喺「預測 vs 賽果」揀一場**已完結並已結算**嘅賽事，系統用**開賽前鎖定嘅機率**
同 **90 分鐘賽果**，生成一段 120–180 字繁體中文摘要，講清楚：

- 引擎預測咩（主／和／客三格邊格最高、幾多機率）；
- 實際賽果；
- 命中／失準嘅可核實原因（只用系統入面已有嘅數字，例如預期入球 λ、
  主客機率距離、波膽矩陣最高格、走水／讓球線）。

## 三、重開時嘅硬性規則

1. **唔准作資料**：只用系統已有嘅數字；唔准提傷兵、陣容、天氣、消息面等系統冇嘅資訊。
2. **唔准改凍結**：預測欄、λ、矩陣、指紋一律只讀；解說文字另存或即时生成，永不回寫。
3. **紅燈／未入戰績場次**：可以生成，但要喺輸出上面標明該場唔入公開戰績。
4. **只講 90 分鐘**：加時、點球唔計。
5. **失敗要照實講**：讀唔到凍結列或生成失敗，顯示錯誤提示，唔准用估算填補。
6. **成本閘**：任何時候都要有額度用量監控；超過預算即自动關掉。

## 四、成本方案（點解而家唔開）

- 舊做法：每撳一次「生成解說」就調用一次 AI Gateway → 用量不可預測。
- 用戶要求嘅方向：**唔耗 AI 額度嘅本地生成**，并且**賽後自動跑一次**（唔係逐次即席生成）。
- 本地生成嘅前提（沙盒驗證過）：本機冇 `ollama`／`llama-server`，亦冇 `transformers`；
  而且部署環境係 edge worker runtime，唔可以喺端點內跑大型模型。
  所以可行路徑只可以係：
  1. 喺**离线／自建**環境（有 GPU 或足夠 RAM 嘅機器）用細模型逐場預生成，
     結果寫入一份只讀檔案（例如 `reports/match-explanations/<date>.json`），
     前端只負責讀同顯示；或
  2. 用規則式模板（純程式，唔用任何模型）由凍結數字派生句子。
- 兩條路都要遵守第三節全部規則，尤其「唔准作資料」同「唔准改凍結」。
